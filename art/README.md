# 美术资源与建模交接

| 目录 | 保存什么 |
| --- | --- |
| `source/models/` | 可继续编辑的 Blender / Maya 等模型源文件 |
| `source/textures/` | PSD、分层纹理等可编辑源文件 |
| `exports/` | 待审阅、待接入引擎的 FBX 等导出物 |
| `references/` | 可合法保存的参考图及说明；来源不明时仅登记链接 |

本次仅建立目录，没有迁入模型或图片。

## 1 号楼优先

以墙体、门窗、楼板、楼梯、栏杆与废墟掩体为基础模块。保留已有成果，先检查比例、门洞、通行净空、枢轴和碰撞需求，再决定细化范围。命名可采用 `Building01_Wall_A`、`Building01_Stairs_A`。

## 从源文件到工程

1. 在 [资源登记表](../docs/ASSET_REGISTER.md) 记录来源、使用权限、源软件版本和依赖。
2. 保存可编辑源文件；外部贴图使用可恢复的相对路径或软件支持的打包方式，避免只依赖个人磁盘。
3. 导出用于引擎的格式，核对单位、朝向、枢轴、材质、UV 和动画；Blender 与 Unity 的轴向约定不同，实际以导出预设和引擎内结果确认。
4. 待接入时放入 `exports/`；正式采用后，以 Unity `Assets/_Project/Art/` 下的导出物为权威副本，避免长期保存两份相同导出文件。
5. 由 Unity 生成导入元数据；已有资源重新导出时保留原 `.meta`，不要更换 GUID。
6. 可编辑源文件和必要的运行资源都应可恢复；只提交 FBX 不能替代源文件备份。

## 二进制协作

`.gitattributes` 已让常见模型、图像和音视频格式进入 Git LFS，扩展名大小写均覆盖。单个源文件尽量由一人编辑，交接前先推送；LFS 不会替你自动合并两份模型。

超大素材、渲染过程文件、整包备份和不允许公开分发的资源留在适当的外部存储，登记版本与校验值。`external/` 和 `backups/` 只是本地忽略目录，不是备份服务。
